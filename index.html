How to read this page

AI work comes with its own vocabulary. Here are the words that appear below, translated. If you only read one thing on this site, read this.

Word error rate (WER)
How many words a speech-to-text tool gets wrong. 0% is a perfect transcript.
Fine-tuning
Teaching an existing AI model extra lessons on your own data, rather than building one from scratch.
Pre-registered gate
A pass mark written down before the work starts, so the result can't be argued with afterwards.
Latency (p95)
How long the slowest 1-in-20 requests take. Lower is better; p95 means 95% of requests beat it.
Inference
When a trained model actually answers a question. Training is the homework; inference is the exam.
Local / on-device AI
A model that runs on your own computer instead of someone's server, so your data never leaves the machine.
BLEU
The standard 0–100 score for "how close is this translation to a human's?"
Offline-first
The app works with no internet connection, and only goes online if you ask it to.
CI/CD
Automatic checks that run every time code is published, so a broken release can't go live.
Retrieval (RAG)
Looking through your own documents first, then answering using what it found.
Licence audit
Checking you are allowed to use a dataset before you build on it — not after you launch.
Baseline
The number you had before you started, so any improvement is real rather than imagined.

01 — Flagship

Closing the AI gap for Yoruba

The best speech-recognition tool available gets Yoruba badly wrong — 92.6% of words. This project closes that gap on a $400 budget, with every number documented in public.

Aso Oke

In development

Yoruba speech-to-text & translation · Solo, built in public

I measured the starting point first, then built against it: a custom text-cleaning tool that keeps Yoruba spelling consistent (tone marks change a word's meaning, so ẹ and e are different letters, and it was checked against 200 real sentences), a data pipeline where every source was licence-checked before use, and a pass mark written down before any result existed — so I couldn't move the goalposts afterwards.

The most interesting outcome is the one that didn't go to plan. I trained the industry-standard speech model myself — eight passes over Yoruba speech — and it still got 61.4% of words wrong, failing the pass mark I'd set. A model I'd never trained on, used exactly as its makers released it, got 32.0%, and was the one selected to ship. I chose it over my own model and documented exactly why.

The translator was less lucky. It failed both of its own gates — accuracy (11.7 out of 100 against a pass mark of 25) and speed (7.4 seconds against a 3-second limit) — so it launches with a visible disclaimer rather than pretending to be finished. One cheap test ruled out the obvious suspect and pointed at the real one; the fix is scheduled, not claimed.

  • 32.0% of words wrong on a held-out test set (817 clips), against 92.6% for the best tool available
  • 27.7% on speakers it had never heard — the score isn't inflated by data it had already seen
  • 32.8% on women's voices — the standard test set is entirely male, so I measured this separately
  • 4.12s to answer in 95% of requests, on one rented graphics card
  • 60.6 points better than the model I started from

05 — About

How I work

I came to AI from business intelligence — a decade of turning messy data into decisions, and a habit of asking what a number actually means before anyone acts on it. That habit is why this portfolio is built around measurement rather than demos.

My operating principles are simple. Define the bar before you build. Write down the threshold that makes a thing shippable, then let the result decide. Check the licence before you build the baseline. Half my architecture decisions on Aso Oke came from checking what I was allowed to use, and one of them — swapping one translation model for another — would have permanently blocked charging for the product if I'd found it at launch instead of in Week 1. Say what doesn't work. The published model cards and field reports are as explicit about the gaps as the wins.

I'm currently deep in speech recognition for languages that big tech has almost no data for — Yoruba is one of them — and building AI tools that run entirely on your own machine, because privacy, cost and working offline shouldn't be afterthoughts.
